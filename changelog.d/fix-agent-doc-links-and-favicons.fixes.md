- The `brando` section `mix brando.install` and `mix brando.gen.agents` write to `AGENTS.md`, and the skills they copy, name Brando's files where the application has the dependency (`deps/brando` for Hex or Git, the checkout for a `path:` dependency), and the shipped usage rules link relative to themselves, so their links resolve with a path dependency too. A rerun of `mix brando.gen.agents` updates a `brando` section you have not edited; `mix brando.gen.agents --refresh` updates the skills.

- The installer adds `ico` to the web module's `static_paths/0`, so the `favicon.ico` it puts in `assets/frontend/public/ico/` is served, and the CMS root layout links it inside `<.head>`, with commented lines for SVG, dark-mode, PNG and Apple touch icons. A versioned `mix brando.upgrade` adds `ico` to `static_paths/0`; it leaves existing layouts alone.
  Link the icons in your root layout (`lib/my_app_web/cms/layouts.ex`, and each site frontend's `Layouts`) inside `<.head>`: replace `<.head conn={@conn} />` with
  `<.head conn={@conn}><link rel="icon" href="/ico/favicon.ico" sizes="any" /></.head>`, and restart the server after `static_paths/0` changes.
