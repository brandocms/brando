- Saving a module in the module editor no longer stores Off for the Autoplay, Lazy load, Controls, Loop and Muted settings of a video ref or a media ref's video template that nobody touched, which made blocks from the module load their video eagerly; they show Default / On / Off, as the video drawer does.
  Run `mix brando.gen.migrations` for `brando_255`, then `mix brando.migrate` before the new release starts.
  In a release, run `bin/my_app eval "MyApp.ReleaseTasks.migrate()"` from the new release.
  `brando_255` clears every stored Lazy load Off on video refs and media refs' video templates, in modules and in blocks, in every environment; Autoplay, Loop, Muted and Controls keep what is stored. To keep a ref eager, set Lazy load to Off on it again after the upgrade. A module from release definitions whose file sets `preload: false` gets that Off back from the next release that changes the module. Run the migration once: an Off set after rolling it back is cleared again by a second run.
  Pages show the change once they are rendered again, which the 0.55 upgrade's "Repair derived data" step does (`mix brando.entries.resave`; in a release, `bin/my_app rpc "Brando.Content.Resave.run()"`).
