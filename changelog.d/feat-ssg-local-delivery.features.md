- A static site can be served by the installation itself: with the deploy strategy "Served by this installation" (`:local`), a deploy or rollback records the build as published, and the live environment's domain answers from it on the next request, on every node, with its 404 page for a path the build lacks, its redirects, `ETag` revalidation and a year's caching for content-addressed assets.
  Run `mix brando.gen.migrations` for `brando_230`, then `mix ecto.migrate`; with tenancy enabled the application does not start until it has run. With several nodes, keep `sites/` on storage they all share. List an application's own paths that must keep reaching Phoenix on such a host with `config :brando, Brando.SSG.LocalDelivery, dynamic_paths: ["/api"]`, and turn the strategy off for every site with `config :brando, Brando.Sites.DeployConfig, local_delivery: false`.
