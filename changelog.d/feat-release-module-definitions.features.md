- A release's `priv/modules` can be reviewed and applied in production: each database records the module definitions applied to it, so a release's definitions are planned against it rather than the developer's lockfile, superusers see on the dashboard and in Block modules what waits, and `bin/my_app rpc 'Brando.Content.Definitions.Release.status()'` / `apply!/2` (`mix brando.modules plan --release` / `apply --release` in development) review and apply them, and `apply!/2` waits until the affected entries have rendered.
  Run `mix brando.gen.migrations` for `brando_231`, then `mix brando.migrate` and `mix brando.migrate --tenants` before the new release starts.
  In a release, run `bin/my_app eval "MyApp.ReleaseTasks.migrate()"` and `bin/my_app eval "MyApp.ReleaseTasks.migrate_tenants()"` from the new release.
  Add `config :brando, Brando.Content.Definitions, release_path: "priv/modules"` to `config/config.exs` (`"priv/modules/{site_key}"` with several sites) to turn it on.
