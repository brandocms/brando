- A page's canonical link, `og:url`, alternates and JSON-LD `@id`s and `url`s now name one URL without a trailing slash, however the page was requested (`/about/`, a query string, a static build), whatever order the controller calls `put_meta/3`, `put_json_ld/3`, `put_hreflang/2` and the new `put_page_url/2` in, and with one alternate per language: `@id`s are `https://example.com/about#webpage`, no longer `…/about/#webpage`, and the items of a datasource block's `json_ld` are `…/news/a#article`, the `@id` the entry's own page gives it. The page's URL is the one given to `put_page_url/2`, else that of the entry given to `put_hreflang/2`, else the request URL, as the meta guide's "Canonical URL" describes.
  Entries keep the old `@id`s in the JSON-LD their blocks stored until they are rendered again: run `mix brando.entries.resave --yes`, then restart the server or use Configuration → Cache → Empty all caches.

- What a layout or controller reads from the conn keeps its shape, with these differences: the first entry of `conn.private.brando_hreflangs` is the page's URL (with `put_hreflang/2`'s list or `{helper, args}` form, the request path without a trailing slash, where it was the router's `path_info`); the entities in `conn.assigns.json_ld_entities` and `conn.assigns.json_ld_main_entity` name the page's URL when `put_json_ld/3` is called and the new `@id` form, and the head builds an entity again when `put_hreflang/2` or `put_page_url/2` changes that URL later (`Brando.Plug.HTML.json_ld_entities/1`); and a `brando_hreflangs` an application puts itself no longer sets the canonical link.

- The 404 and 410 pages, and other error responses, get no canonical link, `og:url` or JSON-LD `WebPage` node, which named the requested path (on a static build, the build's probe path for every missing page).
