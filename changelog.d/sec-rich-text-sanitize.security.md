- Rich text (text refs and `:rich_text` fields) is parsed as browsers parse it (html5ever, through MDEx) and stored as that parse serializes, without comments and without `xmp`, `noembed`, `noframes`, `noscript`, `plaintext`, `template` and `title` elements; markup that hid an event handler from the old check in a comment, a CDATA section or such an element is refused or left out. Text the editor writes is stored as it is; other markup may be normalised (`<br/>` to `<br>`, single to double quotes, a `tbody` in tables, text placed directly inside a table moved before it as browsers do (Liquid loops between table rows in old or imported text stop working), unknown tags unwrapped, and a link with an address scheme no browser or app is known for loses its address).
- Content assistant and MCP proposals check SVG as browsers parse it, and Markdown as the HTML it renders, so a script link in Markdown is reported as unsafe text.
