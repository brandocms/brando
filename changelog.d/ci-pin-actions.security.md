- `mix brando.install --domain` no longer trusts every subdomain of the domain in `check_origin`: it lists the domain, its `www.` host (the name without `www.` for a `www.` domain), the staging host and each `--origin`, so a page on a subdomain someone else controls cannot open a LiveView socket with an editor's cookies. Add any other host that serves LiveView (multi-site domains, an admin on its own host), or pass `--origin '//*.example.com'` when every subdomain is yours.
  Applications installed before keep their `check_origin`; replace `"//*.example.com"` in `config/prod.exs` with the hosts the application serves (`"//www.example.com"`, `"//staging.example.com"`), or keep the wildcard if every subdomain is yours.

- The generated Dockerfile installs `sentry-cli` at an exact version (`ARG SENTRY_CLI_VERSION`) in a step without the Sentry token, and the upload step only runs the installed binary, instead of fetching the newest 3.x release with `npx` while the token was exported.
  Applications generated before can do the same: add `ARG SENTRY_CLI_VERSION=3.8.2` and `RUN npm install --global @sentry/cli@${SENTRY_CLI_VERSION}` before `pnpm build` in the `assets_frontend` stage, and call `sentry-cli` instead of `npx --yes @sentry/cli@3` in the upload step.
