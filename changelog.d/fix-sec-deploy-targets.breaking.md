- With `tenancy_mode: :multi`, rsync and S3 deploys need the operator's list of destinations, new `s3_targets` beside `rsync_targets`, and a `{site_key}` placeholder binds an entry to one site, so someone who may deploy one site cannot point it at another's directory, prefix or bucket. Targets are checked when saved and when a build deploys; an S3 bucket with no prefix passes a list only if an entry names it exactly, and an S3 prefix may not hold `.`, `..`, empty segments or URL syntax. With one site and no list, deploys work as before.
  Add the destinations your sites deploy to, with `{site_key}` where the layout allows it: `config :brando, Brando.Sites.DeployConfig, rsync_targets: ["deploy@static.example.com:/srv/sites/{site_key}"], s3_targets: ["s3://static-bucket/sites/{site_key}"]`. An entry without the placeholder, whether an exact destination or a shared parent ending in `/`, grants every site, so an existing `rsync_targets` parent keeps working but leaves the sites open to each other until it uses `{site_key}`.
  Existing builds deploy, and roll back, once their target is listed; until then a refused deploy or rollback says so in the build log. A site whose target does not fit needs a new target under Admin → Config → Publishing and a new build.
