- A stored render in which a block template fails (a Liquid parse error, a list that is nil, an exception in a Liquid or HEEx template) is no longer stored with the error in the page: the entry keeps the HTML it had, and the failure is reported with each block's module and error. An editor's save still saves the entry and shows an alert; the render job is cancelled rather than retried, and `await_refresh/2`, failed-job notifications and `mix brando.entries.resave` name it. The live preview still shows the error in the page.
  A template that iterated over nil used to store an HTML comment in its place; its entries now keep their old HTML until it is fixed. Run `mix brando.entries.resave` and fix the templates it names, as the migration guide's step 4 says.
  Code that matches on `Brando.Content.Blocks.render_entry/2` handles `{:error, {:render_failed, failures}}` (`Brando.Villain.RenderFailure` structs). `Brando.Content.Blocks.render_all_block_fields_and_add_to_changeset/3` is removed: call `Brando.Content.Blocks.render_fields/3`, which renders without storing, and put each field's HTML in `rendered_<field>`.
